# CLAUDE.md

`pagetriage` is a deterministic, non-ML page-content analyser for degraded scanned legal documents,
written in Rust. One core crate compiles to native, Python (PyO3), and browser/Node WASM. The same
input must give the same output, byte for byte, on every one of them. Module codes (M1, M10, ...)
are defined in `docs/modules.md`; the papers behind them are in `docs/REFERENCES.md`.

## Rules

1. Never add a dependency that loads a model file or uses a neural network. Allowed: hand-designed
   features, fixed thresholds, and at most about 50 interpretable coefficients per detector, stored
   as readable TOML and reproducible from a script. Not allowed: neural nets, random forests, SVMs
   or any model file loaded at runtime, learned codebooks (k-means vocabularies).
2. Every dependency of `pagetriage-core` must compile to `wasm32-unknown-unknown`, unless it sits
   behind a non-default cargo feature.
3. Every threshold lives in `crates/pagetriage-core/params/*.toml` with a comment naming its source
   or "tuned on <set>". No magic numbers in detector code.
4. Every new detector ships a docs page (`docs/detectors/<name>.md`, with a failure gallery), a
   golden test input and report in `tests/golden/`, and a benchmark line before it merges.
5. Keep `pdf-inspector` as an upstream dependency and file issues or PRs rather than forking it.
6. No `unsafe` outside the FFT code and the FFI crates (`pagetriage-py`, `pagetriage-wasm`).
7. The determinism gate (`scripts/determinism.sh`) runs in CI on every PR. Never weaken it to make
   a change pass: a golden diff is a behaviour change and must be reviewed as one.

## Determinism rules (enforced by `clippy.toml` where possible)

- No `f64::exp/ln/powf/sin/cos/...`. The platform libm differs in the last ulp between glibc, Apple
  libm and WASM. Use `pagetriage_core::math` (backed by the pure-Rust `libm` crate).
- No `HashMap`/`HashSet`: iteration order is randomised per process. Use `BTreeMap`/`BTreeSet`.
- Sum floats over pixels with `math::pairwise_sum` (fixed order), never with an order that depends
  on threads or SIMD width. No fast-math.
- The core never reads the clock, the environment or the filesystem. Timings are measured by the
  host. `std::time::Instant` also panics on `wasm32-unknown-unknown`.
- Reports go out through `schema::to_canonical_json` (sorted keys, floats rounded to 6 decimals,
  `-0.0` normalised). Check non-finite numbers where a detector produces them (`math::finite`,
  `Evidence::new`): `serde_json` would silently turn NaN into `null`.
- Do not enable `serde_json`'s `preserve_order` feature anywhere in the dependency tree.

## Commands

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test                              # core + cli (the default members)
scripts/determinism.sh                  # native + Python + WASM vs tests/golden (needs maturin, wasm-bindgen-cli, wasm-opt, node)
UPDATE_GOLDEN=1 cargo test -p pagetriage-core --test golden   # after an intentional change; review the diff
UPDATE_SCHEMA=1 cargo test -p pagetriage-core --test schema   # after changing schema.rs
python3 -I tests/golden/gen_inputs.py   # regenerate the synthetic golden inputs
```

`cargo test` skips `pagetriage-py` and `pagetriage-wasm`: they need maturin and the wasm-bindgen CLI
to build. The wasm-bindgen CLI version must equal the `wasm-bindgen = "=x.y.z"` pin in
`crates/pagetriage-wasm/Cargo.toml`; `cargo install` puts it in `~/.cargo/bin`.

## Data and privacy

- Never commit real document pages. Deeds contain PII (names, Aadhaar fragments, addresses).
  Golden inputs are synthetic and generated by `tests/golden/gen_inputs.py`.
- Benchmark datasets (DIBCO, Tobacco800, ...) are fetched at runtime into `bench/data/`, which is
  gitignored. Their terms forbid redistribution or grant no licence.
- `PLAN.md` is local-only and gitignored. Do not reference it from committed files; put anything a
  reader needs in `docs/`.
